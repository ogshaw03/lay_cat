BYO R2 SETUP

自分の Cloudflare R2 を LayCAT に接続する

BYO（Bring Your Own）R2 プランで、自前の Cloudflare アカウント上に LayCAT 用のストレージを構築するための手順書です。所要時間の目安は 30〜60 分。

⚠ この手順書について

本ページには Cloudflare / Firebase のウェブ管理画面での操作が含まれます。両サービスとも UI（メニュー名・ボタン位置・画面レイアウト）はアップデートで予告なく変わることがあります。

本文中の画面名やボタン名は執筆時点の目安です。実際の画面で見つからない場合は、その要素の役割（例：「新規バケットを作る」「シークレットを追加する」）から近い項目を探してください。

手順の 順序と目的（何をどこに登録するか）は基本的に変わりません。迷ったら FAQ の末尾リンクから最新の公式ドキュメントを確認してください。

1
前提と全体像

必要なもの

  • Cloudflare アカウント（無料枠あり／クレジットカード登録は R2 有効化時に必要）
  • ローカル環境：Node.js 18+ と npm（Worker デプロイ用の wrangler CLI に必要）
  • LayCAT のログインアカウント（Google／メール認証）
  • LayCAT 運営から共有される接続情報（Firebase の projectId、アクセス管理登録の依頼先）

この構成でできること

プロジェクトのメタ情報（laycat.project.json）と動画・画像・リールデータを、自分の Cloudflare アカウント配下の R2 バケットに保存できるようになります。データは常に自分の管理下にあり、退会時も自分でバケットごと削除できます。

データフロー

[ブラウザ (LayCAT)] │ ① Firebase Auth でログイン → ID トークン取得 │ ② PUT/GET/DELETE https://<worker>/api/r2/<projectId>/<path> ▼ [Cloudflare Workers (laycat-r2-api)] │ ・ID トークンを Firebase 公開鍵で検証 │ ・Firestore の アクセス管理 (laynaAccess) を照合 │ ・key プレフィックスが projectId 直下か検査 ▼ [Cloudflare R2 バケット (laycat-projects)] projects/<projectId>/laycat.project.json projects/<projectId>/media/<file> projects/<projectId>/reels/reels.json
ポイント： R2 バケットは非公開のまま運用します。ブラウザから直接 R2 は叩かず、必ず Worker を経由するため、S3 互換の API トークンや署名付き URL の管理は不要です。
2
Cloudflare アカウント準備

2-1. サインアップ

https://dash.cloudflare.com/sign-up でアカウント作成。既に持っていればスキップ。

2-2. R2 の有効化

ダッシュボード左サイドの R2 Object Storage を開き、案内に沿って有効化します。初回のみクレジットカード登録が必要ですが、無料枠内なら課金は発生しません。

項目無料枠（月あたり）
ストレージ10 GB
Class A リクエスト（PUT / POST / COPY / DELETE / LIST）100 万回
Class B リクエスト（GET / HEAD）1000 万回
エグレス（データ転送）完全無料
MEMO： R2 の最大の特徴はエグレス無料です。動画を再生・ダウンロードするたびに転送料金がかさむ心配はありません。
3
R2 バケットの作成

R2 のダッシュボード画面から新規バケットを作成します。ボタン名は概ね「Create bucket」相当です。

入力項目

項目値備考
Name（バケット名）laycat-projects半角小文字・ハイフンのみ。命名は任意だが、以降の手順は本ドキュメントの名前で統一。
LocationAutomatic特別な要件が無ければ自動選択で OK。日本ユーザー中心なら APAC 明示も可。
Storage ClassStandard選択肢が出た場合。Infrequent Access はコストが逆に上がるので選ばない。
Public access無効のまま公開しません。Worker 経由でのみアクセスします。
注意： Allow Access／Public URL のような「公開する」設定を有効にしないでください。有効化するとバケット内の全ファイルが誰でも読める URL で公開されます。

作成完了後、以下の 2 つの値を控えておきます（次のステップで使用）。

  • バケット名（例：laycat-projects）
  • アカウント ID（R2 ダッシュボード右側や、アカウントホームの URL に含まれる 32 桁の英数字）
4
Worker（プロキシ API）のデプロイ

R2 バケットへのアクセスを仲介する Cloudflare Workers を作成します。Workers Free プランで動きます（1 日 10 万リクエストまで無料）。

4-1. wrangler CLI をインストール

npm i -g wrangler
wrangler login

ブラウザが開いて Cloudflare のログイン画面が出るので、対象アカウントで承認します。

4-2. Worker プロジェクトの雛形を作る

mkdir laycat-r2-worker && cd laycat-r2-worker

LayCAT リポジトリの worker/laycat-r2-api.js をこのフォルダに index.js としてコピーします。運営から Worker スクリプト本体を受け取っている場合はそれを使ってください。

cp /path/to/lay_cat/worker/laycat-r2-api.js index.js

4-3. wrangler.toml を作成

同じフォルダに wrangler.toml を作り、下記内容を書き込みます。

name = "laycat-r2-api"
main = "index.js"
compatibility_date = "2025-01-01"

[[r2_buckets]]
binding = "R2"                       # Worker から env.R2 でアクセス
bucket_name = "laycat-projects"      # ステップ 3 で作ったバケット名

[vars]
FIREBASE_PROJECT_ID = "layna-app"    # 運営から共有される projectId
ALLOW_ORIGIN = "https://ogshaw03.github.io"
# 開発時はカンマ区切りで複数許可可：
# ALLOW_ORIGIN = "https://ogshaw03.github.io,http://localhost:8080"
MEMO： binding = "R2" の "R2" という文字列は Worker スクリプトが参照する変数名です。変更しないでください（変えるとスクリプトが動きません）。

4-4. デプロイ（初回はまだしない）

この時点ではまだシークレット（ステップ 6）が未登録なので、動作させても認証エラーになります。ステップ 5 → 6 を完了してからデプロイします。

5
Firestore サービスアカウント設定

Worker から Firestore の laynaAccess（アクセス管理）を読み書きするために、Firebase の サービスアカウント秘密鍵を発行します。

注意： ここは運営から共有される情報を使う手順です。BYO ユーザーが自分の Firebase プロジェクトを新たに作る必要はありません（LayCAT の Firebase を Worker から読むだけ）。運営から Service Account JSON、または「発行手順を実行する Firebase コンソールへの案内」を受け取っている前提です。

5-1. Firebase コンソールでサービスアカウント JSON を発行

運営から共有された Firebase プロジェクトに入り、下記の位置で 新しい秘密鍵を生成します。

プロジェクト設定 → サービス アカウント → 新しい秘密鍵の生成

Project settings → Service accounts → Generate new private key

ヒント： このメニューは Firebase コンソール左上の歯車アイコンから開ける「プロジェクト設定」の中にあります。UI 表記が変わっている場合は「service account」「秘密鍵」で画面内検索してください。

5-2. ダウンロードした JSON の扱い

クリックすると JSON ファイルが 1 個ダウンロードされます。中身はこんな形です：

{
  "type": "service_account",
  "project_id": "layna-app",
  "private_key_id": "…",
  "private_key": "-----BEGIN PRIVATE KEY-----\n…\n-----END PRIVATE KEY-----\n",
  "client_email": "firebase-adminsdk-xxxx@layna-app.iam.gserviceaccount.com",
  …
}
危険： この JSON は Firestore への読み書きが可能な認証情報です。Git にコミットしたり、共有ドライブに置いたり、Slack で投げたりしないでください。Worker Secret に登録したら、ローカルからは削除して構いません。
6
Worker シークレット・環境変数

6-1. サービスアカウント JSON を Secret として登録

laycat-r2-worker フォルダで下記を実行します。

wrangler secret put FIREBASE_SERVICE_ACCOUNT

プロンプトが「Enter the secret value:」と表示されたら、ステップ 5 でダウンロードした JSON の中身をそのまま貼り付けます（改行を含む複数行のままで OK）。改行の扱いがうまくいかない場合は、JSON を 1 行に整形（内部の \n はそのまま残す）してから貼り付けます。

MEMO： Worker Secret はダッシュボード上でも読み出せない暗号化ストレージに保存されます。wrangler.toml や Git には残りません。

6-2. デプロイ

wrangler deploy

成功すると、こんな URL が発行されます：

https://laycat-r2-api.<your-subdomain>.workers.dev

この URL を控えておいてください（ステップ 7 で LayCAT に登録します）。

6-3. Cloudflare ダッシュボードでの追加設定（任意）

デプロイ後、Cloudflare の Workers & Pages から作成した Worker を開き、以下を確認/追加できます。

  • 環境変数（ALLOW_ORIGIN 等）を GUI からも編集可
  • カスタムドメインを設定して https://r2.your-domain.com のような URL に置き換え可
  • ログ／メトリクスで Worker の呼び出し数・エラー率を確認可
7
LayCAT 側の接続設定

7-1. Worker URL を LayCAT に登録

LayCAT を開き、環境設定（歯車アイコン）から Cloudflare R2 エンドポイント欄に、ステップ 6 で発行された Worker の URL を貼り付けます。

MEMO： BYO R2 の UI は現在準備中です（β 期間中は運営が代行して設定します）。運営に Worker の URL を伝えてください。

7-2. アクセス許可の登録

Worker は LayCAT の laynaAccess に登録されたメールアドレスからのリクエストのみ受け付けます。プロジェクトを操作するメンバーのメールアドレスを運営に共有し、アクセス管理コンソールから登録してもらってください。

7-3. 新規プロジェクト作成時に R2 モードを選択

プロジェクト作成画面で、保存先として Cloudflare R2 を選択します。既存のフォルダ運用プロジェクトはそのまま維持され、影響を受けません。

ヒント： ローカルフォルダ運用と R2 運用はプロジェクト単位で共存できます。徐々に新規から R2 に切り替えていく運用が可能です。
8
動作確認

8-1. R2 プロジェクトを 1 つ作る

LayCAT で新規プロジェクトを R2 モードで作成し、動画を 1 本アップロードします。アップロード中にエラーが出なければ OK。

8-2. Cloudflare R2 ダッシュボードで確認

R2 のバケット詳細画面を開き、以下のキーが作られていることを確認します。

projects/<projectId>/laycat.project.json
projects/<projectId>/media/<video-id>.mp4

8-3. Worker ログを確認

Cloudflare ダッシュボードの Workers 画面から、リアルタイムログ（Logs / Real-time Logs）を開くと、LayCAT からのリクエストが 200 系で返っているのが見えます。401/403 が続く場合はステップ 10（トラブルシュート）を参照。

トラブルシュート

デプロイ時のエラー

  • Missing binding: R2 → wrangler.toml の [[r2_buckets]] セクションが抜けている／バケット名が誤っている。
  • Authentication error / You need to login → wrangler login を再実行。ブラウザで別アカウントにログイン中だと誤ったアカウントで承認しがち。
  • Script too large → 巨大な依存を入れていないか確認（本 Worker は依存なしで動くはず）。

ランタイムエラー

  • 401 / 403 → Firebase ID トークン期限切れ、laynaAccess に未登録、別プロジェクトのキーへアクセス、のいずれか。LayCAT で再ログインして試す。
  • 404 → バケット内にファイルが無いだけ。初回書き込み前の GET は 404 が正常。
  • CORS エラー → Worker の ALLOW_ORIGIN に現在のオリジンが含まれていない。wrangler.toml の [vars] を修正して wrangler deploy。
  • 500 Internal Error → Worker のログ（Real-time Logs）でスタックトレースを確認。多くは FIREBASE_SERVICE_ACCOUNT Secret の JSON が壊れているケース。

データ関連

  • プロジェクトを削除したのに R2 にファイルが残る → LayCAT からの DELETE は非同期でバケット内をループ削除します。数十秒〜数分待って再確認。残る場合は Cloudflare ダッシュボードから手動削除可。
  • ローカル運用 → R2 移行 → 現状は手動移行のみ（新規プロジェクトを R2 で作り、動画を再アップロード）。自動移行ツールは今後対応予定。

よくある質問

BYO と Managed の違いは？

Managed（運営提供）： 運営の R2 バケットに保存。セットアップ不要ですぐ使える。ストレージ・転送費用は運営持ち。

BYO： 自分の Cloudflare アカウントに保存。セットアップは 30〜60 分必要。ストレージ・転送費用は自己負担だが、無料枠内で収まる想定。データを完全に自分の管理下に置ける。退会時もバケットごと自分で削除できる。

1 つの Worker を複数チームで共有できますか？

技術的には可能ですが推奨しません。Worker のコストとリクエスト数が全チーム分になるうえ、障害時の影響範囲も広がります。1 チーム = 1 Worker + 1 バケットの運用を推奨します。

バケット名を変えたい

wrangler.toml の bucket_name を書き換えて wrangler deploy するだけです。ただし既存データの移行は自動では行われません。プロジェクトを新規作成し直すか、Cloudflare の Super Slurper 等で内容をコピーしてください。

Cloudflare のダッシュボード表記が本ドキュメントと違う

Cloudflare の UI は年に数回更新されます。本ドキュメントは執筆時点のものなので、細部は変わっている可能性があります。操作の目的（バケット作成／Worker デプロイ／Secret 登録）は変わらないので、UI 内検索や公式ドキュメントで対応する項目を探してください。それでも見つからない場合は運営までお問い合わせください。

途中で失敗したらどうする？

各ステップは単独でやり直せるように分けています。バケット・Worker・Secret はいずれも上書き作成／再デプロイで問題ありません。ゼロからやり直したい場合は、Cloudflare ダッシュボードから Worker とバケットを削除してステップ 3 から再開してください。

Cloudflare 以外のオブジェクトストレージは使えますか？

現状は R2 のみ対応です。S3 / GCS / Backblaze B2 なども構造的には可能ですが、エグレス無料という R2 の利点が動画中心のワークフローに最も適しているため、当面は R2 一本で提供する予定です。
